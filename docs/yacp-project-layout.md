# YACP project layout

Current source policy (2026-10-17): this CrossPoint tree is the single active YACP implementation for all four readers. See [source consolidation](yacp-source-consolidation.md) for recovery decisions, safeguards and current validation. Older source-selection notes are historical.

YACP prioritizes battery efficiency, responsive reading and avoiding unnecessary work on the reading path.

## Reading design rationale

Text anti-aliasing is not enabled by the YACP profile or as a YACP default. Christophe finds that it makes text too blurry and too light, reducing readability. Preserve the user's existing anti-aliasing choice when applying the YACP profile; do not silently force it on or off.

This branch is an unfinished reconstruction on CrossPoint 1.6.5. Its source of truth is the feature matrix, not the list of successful builds. Hardware validation and complete data migration are still required. No public website is built here.

## YACP Home

The YACP theme uses a cover-free typographic card: title, author, cached progress, recorded reading time and the saved remaining-time estimate. Unknown values are shown as `-`. Load the selected book's summary only on Home entry, book selection or an explicit statistics edit. Home rendering must not open or generate a cover thumbnail, scan all recent-book caches or load global reading statistics.

Use input capabilities, not a model-name test, to adapt navigation. X4 Pro retains the Statistics, Autonomy and Menu touch rows, card-to-resume and recent-book swipes. X3, original X4 and X4 Classic use physical buttons and the secondary menu; their card occupies the space otherwise reserved for touch rows. Landscape places the book identity beside its reading summary. Other home themes keep their existing cover layouts.

The card uses twice the theme's content-side padding, leaving wider white margins than the touch shortcut rows. Its hit rectangle follows the drawn card.

The October 16 contextual settings hints and Magic Flash 2X were initially implemented in the separate legacy `Crossink/YACP` checkout (test build `1.7.2-yacp.57`). They have now been adapted to this CrossPoint port's existing option dialog and reader pipeline. The X3 offers Full, Magic Flash and Magic Flash 2X before the frequency setting. A static translation table provides two-line help for the highlighted method or frequency, with Never retaining its persisted value 5 and 60 pages retaining value 6. Touching the help band keeps the dialog open.

The later display-mode revision supersedes that three-choice UI: X3 now offers Magic Flash and Classic (CrossPoint). Magic Flash means two passes on every ordinary text page with text smoothing off. Cadence and smoothing are locked but visible, while their Classic preferences remain stored and return when switching back. Both legacy reinforcement IDs are accepted as Magic Flash. Other devices retain their normal display behavior. See [X3 display modes](magic-flash-mode.md) for persistence, web API and verification details. Physical contrast and energy effects still require device testing.

## Canonical files

| Location | Purpose |
| --- | --- |
| `src/`, `lib/`, `include/` | Firmware and application sources |
| `freeink-sdk/` | Pinned upstream hardware SDK |
| `platformio.ini` | Board profiles, font variants and embedded test version |
| `scripts/build_yacp.py` | Increment version, compile, record the result and preserve its named artifact |
| `scripts/yacp-fonts.json`, `scripts/build_yacp_fonts.py` | Canonical embedded-font specification and generation |
| `lib/EpdFont/builtinFonts/source/` | Font inputs, licenses and notices |
| `scripts/build_yacp_logo.py` | Canonical YACP logo geometry and public/firmware/portal asset generator |
| `assets/brand/` | Generated public SVG/PNG logo and source provenance |
| `src/network/html/*.html`, `*.js` | CrossPoint device portal sources; `scripts/build_html.py` regenerates compressed headers |
| `lib/I18n/translations/` | Translation sources for all supported languages |
| `test/`, `scripts/verify_yacp_*.py` | Host checks and reproducible acceptance scenarios |
| `docs/yacp-port-matrix.md` | Observable features, port decisions and validation status |
| `docs/yacp-migration.md` | Data compatibility, experiments and remaining migration requirements |
| `CHANGELOG.md` | User-visible changes in the reconstruction |

The SVG, PNG, firmware bitmap and portal SVG come from the same geometric definition. Regenerate with `python scripts/build_yacp_logo.py`; do not manually edit the exports or generated headers. The 1,800-byte pre-rotated firmware bitmap matches the frozen YACP logo exactly, and the public SVG is unchanged. Runtime headers are ignored and generated by the PlatformIO hook. A content-hash stamp skips raster generation only when the generator and both output files match. Fresh generation requires Pillow from the existing Python build dependencies. It can also be prepared explicitly before invoking PlatformIO from another Python environment.

## Local generated outputs

`.pio/`, `.pio-simulator/`, `qa-artifacts/`, `dist/`, generated font headers, generated translations, web headers, simulator SDs and personal PlatformIO overrides are not source material for a public site. They stay ignored as applicable. Build reports identify the version, variant, digest and validation limits; a successful compile does not imply a safe installation.

For headless landscape captures, use `SDL_RENDER_DRIVER=software` with `SDL_VIDEODRIVER=offscreen`. The accelerated offscreen backend clips resized landscape output in this environment. This capture setting does not alter firmware sources or the display pipeline on devices.

Simulator acceptance scripts create isolated directories and retain their fixtures. A deliberately invalid fixture belongs to that test alone. Never point these scripts at a mounted reader card.

## Preserved references and archives

The complete previous YACP checkout, including uncommitted additions, is preserved outside this worktree with a file digest manifest. The interrupted CrossInk port remains a separate reference. Neighboring worktrees with ambiguous or active use remain in place. No source history has been rewritten and no commit has been created for this reconstruction.

The archive belongs outside the CrossInk project tree and outside Nextcloud. It contains the original SD snapshot, book excerpts, settings, network data, previous binaries and historical R&D evidence. These private files are not public assets. Canonical source files must not depend on an absolute archive path to compile.

For any future cleanup, verify the absolute target, the inventory and the backup first. Only confirmed disposable generated outputs may go to the Windows Recycle Bin, one item at a time. Stop if that operation fails. No automated recursive deletion is part of this layout.

## Future website inputs

Use the logo in `assets/brand/`, the YACP philosophy above, verified feature descriptions, release notes and approved screenshots of synthetic or otherwise publishable content. Simulator screenshots and added captions use English. Personal EPUB passages, SD contents, credentials, raw logs and unfinished claims remain private. The current feature matrix must not be copied into a website as a list of released capabilities.

Keep the upstream CrossPoint, FreeInk, CrossInk and other contributor credits associated with imported code. Retain their licenses and the separate font notices. Existing CrossPoint documentation in this tree continues to describe upstream behavior unless the YACP matrix explicitly records a change.

## Validation order

Use the versioning wrapper before each compilation. `tiny` is the required Standard build for shared changes. Build all three Standard profiles with `all-local` before general release. Validate synthetic data first, then copied real data, then X3 and X4 Pro hardware before the older X4 and X4 Classic. On devices, check the same reference book, SD access, position, statistics, sleep/wake, and on Pro the Home key, touch and frontlight. Installation and publication require separate authorization.

## Pristine comparison reference

Keep it alongside the original YACP and interrupted CrossInk references until the port has passed acceptance.
