YACP prioritizes battery efficiency, responsive reading and avoiding unnecessary work on the reading path.

# YACP 2.0 beta 3

This corrective beta keeps access to the library and books when an old reading-data import or migration backup fails on a readable microSD card. It also handles cards where an earlier beta already started a migration.

Older preferences and reading positions may not carry over when switching to the CrossPoint base. When an import fails, YACP starts with fresh reading data in `/.yacp-reading-v1`. New preferences and positions are saved there and reused after restart. The old files and unfinished migration remain preserved, and automatic import is skipped while the separate reading store exists.

A folder named `pending` is an incomplete backup. Keep the complete pre-update card backup for rollback and leave the old migration files in place. See the [upgrade and rollback guide](../../README.md#download-and-update).

Verification on the X3 simulator covers a successful legacy migration, a forced settings-write failure after an interrupted migration, and a conflicting partial backup. Each case opens the file browser and an EPUB, advances reading, and checks that the new position and preferences survive a restart. Original reading-data hashes are checked as well. The 163 Python regression tests pass. Physical hardware acceptance is pending.

For hardware verification, use a separate test card on the matching reader model. Open a book, advance several pages, return Home and restart. Check that the book reopens at the saved passage and that a changed preference is retained. Keep the original card and migration folders for recovery.
